# Proxy 并行搜索的 k（每实验卡数）选择指南

> 记录时间: 2026-08-28
> 目的: 系统记录"每个 proxy 实验用几张 NPU（k）"的决策模型、实测锚点、闭式规则与操作流程。生产启动前按本文档三步法确定 k 与 configs_per_iter。
> 适用范围: proxy 搜索阶段（d20 并行实验）。target 阶段固定 ws=8（quadmix 验证过的唯一形态，run-4 实测 18.2s/步），不适用本文档。

---

## 1. 问题定义与硬约束

公共 NPU 卡池（规模波动 10-200 卡，典型 ~32）上运行 proxy 搜索。搜索结构：

```
迭代 1 (n₁ 个实验, 并行) → 屏障: LightGBM 重拟合 → 迭代 2 (n₂ 个实验) → … → 迭代 m (nₘ)
```

要决定：

- **k**：每个实验的卡数（torchrun nproc_per_node），**整个 run 内必须固定**——不同 ws 的梯度归约/数值路径有微小差异，跨实验分数要可比
- **{nᵢ}**：每轮迭代实验数（启动前人为设定，可按池子现状定制）

硬约束：

1. **迭代屏障**：每轮全部实验完成 → predictor 重拟合 → 才能采样下一轮（`iterative_bootstrapper.search_optimal` 顺序循环）。轮内无重叠空间
2. **单实验不可跨节点**：一个实验的 k 张卡必须来自同一节点（torchrun 单机形态）
3. **作业持有到结束**（JobAPI 租约语义，无抢占）；支持节点内部分卡分配
4. 池子是公共的、动态的：启动后可涨可跌，涨跌只影响排队速度，不影响运行中作业

## 2. 成本锚点（实测，2026-08-28）

| 锚点 | 值 | 来源 |
|---|---|---|
| d20 proxy 训练 @1卡 | **60 s/步** | speedrun: 50 步 = 50 min |
| d28 target @8卡 | **18.2 s/步**（bf16_mfu 16.71） | run-4 Step 6: 50 步 = 15.14 min |
| eval 每条成本（全量, @1卡） | gsm8k_cot 3.49s, math_cot_500 3.72s, gpqa 0.146s, arc_easy 0.075s, arc_ch 0.069s, mmlu_stem 0.022s | speedrun 100 条/任务实测 |

**加速比模型**：双锚点反解（t(k) = a + b/k, a ≈ 0-1.5s/60s），S(2)≈1.85, S(4)≈3.5, S(8)≈6.5——近线性。d20@1卡慢（~7% MFU）是小矩阵算子效率低，不是串行开销，可被加卡除；d28@8卡单卡 49 TFLOPS（16.7% MFU）证明卡内 HCCS 通信不构成瓶颈。

**生产单实验成本 T(k)**（d20, 1000 步 ≈ 16.7h@1卡训练 + 全量 eval ≈ 1.9h@1卡, eval 近线性分条）：

| k | 训练 | eval | T(k) | 卡时/实验 k·T(k)（scaling 税） |
|---|---|---|---|---|
| 1 | 16.7h | 1.9h | **18.6h** | 18.6h（基准） |
| 2 | 9.0h | 1.0h | **10.0h** | 20.0h（+7.5%） |
| 4 | 4.8h | 0.5h | **5.3h** | 21.0h（+13%） |
| 8 | 2.4h | 0.3h | **2.8h** | 22.5h（+21%） |

> 注: eval 全量 ≈1.9h@1卡 中 95% 是两个生成任务（gsm8k_cot 1319 条 ≈ 77min, math_cot_500 500 条 ≈ 31min）。若采用 capped eval（--eval-max-per-task）此列会显著缩小，但会进指纹、且子集抽样噪声 ~±0.016 无法支撑精细门值——默认保持全量。

## 3. 调度模型

所有实验时长同构。设池规模 A、并发槽位 C(k)=⌊A/k⌋（按节点装箱，见 §5）：

```
总墙钟  Wall(k) = T(k) × Σᵢ ⌈nᵢ / C(k)⌉     （逐迭代取 ceiling = 屏障语义）
波长    λ = T(k)                              （一波实验的时长）
池利用率 U(k) = N·k·T(k) / (A·Wall(k))
```

两股方向相反的力：

- **Scaling 税**（k·T(k) 随 k +7.5%~+21%）：偏好小 k
- **屏障空转**（迭代尾波填不满 C、小迭代整池闲置）：偏好大 k。**空转损失 30-80% >> 税 7-21%**，故设计越小最优 k 越大

关键洞察：近线性缩放下总吞吐 ≈ A/T(1)，与 k 无关——**k 不改变产出速率，只决定切片方式**（波长 / 单轮样本数 / 节点装箱）。

### 3.1 实算示例（A=32，供对照）

| 设计 {nᵢ} | k=1 | k=2 | k=4 | k=8 | 最优 |
|---|---|---|---|---|---|
| [20,10,5]（N=35） | 55.8h | 40.0h | 31.8h | 28.1h | k=8（需 4 台整 8 卡节点；否则 k=4，仅差 12%） |
| [32,16,8]（N=56） | 55.8h | 40.0h | 37.1h | 39.3h | k=4 |
| [64,32,16]（N=112） | 74.4h | 70.0h | 74.2h | 78.4h | k=2 |

同一池子设计放大 3.2×，最优 k 从 8 降到 2——k 没有全局唯一答案，必须随设计定。

### 3.2 简化闭式（设计可自由定制时）

既然 {nᵢ} 启动前人为设定，最优解是**联合设计**：先定 k，再把所有 nᵢ 取成 C 的整数倍（n_min ≥ C），每一波 100% 填满：

```
Wall = T(k) × N / C        （零空转，C = ⌊A/k⌋ 按节点装箱）
```

几何设计的 snap 规则（设计形状固定时）：**k* ≈ A / n_min**，snap 到 {1,2,4,8}。

## 4. 三个修正约束（套在 k* 上）

1. **波长上限 λ_max → k 下限**。λ_max = "单实验最长可接受时长"，本质是**不可反悔合同的长度**（训练内无 checkpoint：mid_train --save-every 默认 -1，exp 级 resume 只认完成标记；单实验随机失败损失 = k·T(k)；系统性 bug 最坏烧掉 A×T(k) 卡时才暴露；中途人工纠偏/杀 run 的最短间隔 = 一波）：
   - λ_max ≈ 5h → k ≥ 4：适合**首个生产 run / 流程验证期**（半天内确认没跑偏）
   - λ_max ≈ 10-18h → k ≥ 2 或 k=1：适合**流程已验证、无人值守**的效率档
2. **节点形状 → k 上限**。k=8 需要整 8 卡节点空闲（不可跨节点拼卡）；k=4 可用 4 卡节点 + 8 卡节点双实验装填；k=2 兼容一切。启动时按**当时**各节点空闲卡数装箱（见 §5 实例）
3. **池波动 → 用 A_eff 而非峰值**。建议取中位~P25（如 24-32）代入。启动后池子涨跌由队列派发吸收：涨了按同 k 补派（波数自动少于计划），跌了排队变慢（作业持有到结束，运行中不受影响）。**k 一旦定下不改**（分数可比性）

## 5. 启动前三步法（每次生产 run 照做，~30 秒）

**实例：当前空闲 = 6 卡节点 + 8 卡节点 = 14 卡**

第一步——按节点装箱算各 k 的槽位与闲置：

| k | 6卡节点 | 8卡节点 | C 总槽 | 闲置卡 |
|---|---|---|---|---|
| 1 | 6 | 8 | 14 | 0 |
| 2 | 3 | 4 | **7** | 0 |
| 4 | 1 | 2 | 3 | 2 |
| 8 | 0 | 1 | 1 | 6 |

第二步——套 λ_max 与节点形状定 k。取 λ_max=5h（首个生产 run）→ k≥4，但此池 k=4 闲置 2 卡、C=3 太小；放宽到 λ_max=10h → **k=2**（零闲置）。

第三步——{nᵢ} 全取 C 的整数倍（n_min ≥ C），按样本预算定大小。C=7 → [21,14,7]（N=42）：

| 方案 | 设计 | 波数 | 墙钟 | 波长 |
|---|---|---|---|---|
| k=1 | [28,14,14] | 4 | 74.4h | 18.6h |
| **k=2** | **[21,14,7]** | 6 | **60h** | 10h |
| k=4 | [18,12,6] | 12 | 63.6h | 5.3h |

→ **k=2 + [21,14,7]**：墙钟最短、14 卡零浪费。若流程尚未验证、坚持 λ_max=5h，则 k=4 付 +3.6h 墙钟换颗粒度减半——这是显式取舍。

### 5.1 当前决策（2026-08-28）

- **首个生产 run：λ_max ≈ 5h → k=4**。speedrun 已全绿（2026-08-28, STEM 0.1722, 归档 `speedrun_20260828_120406`），但首个生产 run 相对 speedrun 仍是规模跃迁：100B 池全量 embedding（单节点 43h，走 E 里程碑弹性多节点，见 TODO.md）、1000 步 × 全量 eval（单实验 18.6h@1卡 vs speedrun 62min）、RemoteExecutor 混合舰队首次实战（~22+ 并发）——灾难最大损失 ~74 卡时 @32卡池、半天内可确认没跑偏
- **一次全绿后放宽：λ_max ≈ 10h → k=2**（省闲置省税）
- target 阶段不参与本文档决策（固定 ws=8，1000 步 ≈ 5-6.5h）

## 6. 二阶效应（了解即可，不改结论）

- **迭代间开销非零**：LightGBM 拟合秒级，但每轮之间有 nᵢ 次数据 mix（select + 写 parquet，分钟级/次）。k=2 可忽略；k=8（波长 2.8h）约占 3-5%。缓解：队列派发 + 下一轮 mix 与当前波流水线重叠（RemoteExecutor 实现项）
- **wave 模型是上界**：假设实验时长严格同构；实际 ±10-20% 抖动（mix 大小、生成任务 eval 方差），work-conserving 队列自动回填空槽，真实墙钟略低于表值
- **磁盘**（卡时之外的资源约束）：每实验留存 mid ckpt（model+optim 分 rank，exp 复用标记依赖其存在，**不清理**）+ mix 数据 ≈ 6-10GB；100 实验 ≈ 0.6-1TB。断点语义：完成的实验（meta.json rc=0 + 权重哈希）重启直接复用，训练完 eval 未完（.mid_train_ok）只补 eval，search_state.json 原子写——**磁盘写满最多损失在飞的 ≤C 个实验，已完成部分零损失**
- **A=14 实例的 k=1 论证**：k=1 单位卡时产出最高（0.75 vs 0.70 实验数/h），当设计大到每轮填满池子（n_min ≥ A，如 [128,64,32]@A=32）时 k=1 同时是资源与墙钟双最优；但 [21,14,7] 级别设计下 k=1 波长 18.6h、单点失败损失最大，不值
