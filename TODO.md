## Resolved Design Decisions

- **d20 ≈ CLIMB proxy**: scaling_params=435.2M, 1000 iterations, 8 parallel experiments (1 NPU each)
- **d28 target**: auto-detected from meta_*.json checkpoint, not hardcoded in DEPTH_INFO
- **Cluster-count band [3, 15] with τ=0.9**: floor 3 = permissive safety bound (coarse pools keep their natural structure instead of being pinned to 10; paper-faithful = set K_ENHANCED to the paper's fixed K_enhanced — 20 in its main experiment); cap 15 = search-budget bound for our 35-config budget (paper used 112); τ=0.9 (~cos 0.6, on L2-normalized embeddings) rejects merges of semantically distinct clusters inside the band. Paper v2 §3.1 states its own merge threshold (Euclidean 1.5, unnormalized-space — not directly comparable to ours; see docs/paper_deviations.md D5/D6); see the printed merge-profile diagnostics + merge_profile.json per pool. **REVISED 2026-09-04 (prod1 full pool, 116M docs / ~92B tokens)**: extreme skew (one direction-basin holds 99.86% of docs at K=3) makes natural_K(τ) unstable (0.7→49 / 0.8→4 / 0.9→≤3) and the floor degenerate (search collapses to single effective parameter f(w_C0); random arm 383M vs CLIMB ~1B tokens breaks comparability). Decision: fixed K_ENHANCED=14 from the merge-distance ELBOW (largest jump 0.0816 → 12 macro clusters ~7.6B tokens each + 2 dust clusters, 0.07% docs) — the paper's fixed-K semantics on our pool, under the band cap (search budget 35 vs paper 112) and just below the paper's own granularity (main 21, ablations 15/30, ClimbingLab 20). kmeans cache unaffected (keyed on K_init=1000 + pool; kmeans_K1000.npz holds FULL-POOL labels, so a K_ENHANCED change re-runs only prune+merge — seconds)
- **ClimbMix adaptive shards**: calc_climbmix_count(stem_docs, ratio) → ceil(stem_docs * 0.3/0.7 / 500000), clamped [3, 50] — not all 400B
- **Reverse-order download**: shards from MAX_SHARD (6542) backwards, avoids overlap with pretrain shards 0-999

## Known Limitations

- Resume is atomic per experiment/training run, NOT per training step: an interrupted nanochat training restarts from step 0 (partial target checkpoints are deliberately cleared before retrain)
- Fingerprint does not detect: edits inside nanochat-npu, or data files whose names/row-counts are unchanged (content swaps)
- Embedding cache staleness: pool cache keys cover (shard manifest, model, truncate len, sample-size-if-subsampled) + row-count guards on load, but a same-size content swap inside a shard still hits the old cache (same limitation as fingerprints, content-keyed by size only)
- Predictor refit on resume assumes LightGBM determinism (same accumulated data → same model); verified identical weights in local integration tests
- quality_cluster discovery breaks when K_init > number of domains (centroids shape error) — unused in production (embedding_cluster)
- NPU embedding compatibility relies on the stella buffer repair; re-verify NaN=0 after any sentence-transformers upgrade
- ClimbMix shard count is adaptive (3-50), not full 400B dataset — only enough to match 30% of STEM doc count
- d28 DEPTH_INFO requires meta_*.json checkpoint for auto-detection; without checkpoint, raises ValueError
- STEM data fact density D unknown — cannot determine if subdisciplines cross phase transition threshold
- Intentional deviations from paper documented in docs/paper_deviations.md (12 items: budget/sampling/selection/LightGBM/cluster-band/τ/random-shortfall/metric/70-30-mix/scale/chars-4/eval-cap) + docs/scoring_metric_design.md (SNR score, 70/30 anti-forgetting mix, chars/4 token estimation)
